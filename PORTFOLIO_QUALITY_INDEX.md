# Portfolio quality and recruiter-review index

Last inventory: 2026-11-03. This is a navigation and follow-up document, **not** a certification of test success, security compliance, license ownership or job readiness.

## Five improvement tracks

1. **Secret hygiene:** Each repository has a security-oriented audit workflow. Public-repository workflows include verified-secret scanning jobs that use full Git checkout; only completed workflow runs establish a specific scan result. Keep separate credential rotation and incident-response procedures.
2. **GitHub Actions and dependencies:** Pin action dependencies, use minimum permissions, avoid persistent GitHub credentials and review Dependabot proposals against supported compatibility.
3. **Tests and correctness:** Validate results on the [GitHub Actions runs](https://github.com/JamieChristian22) for each repository. Queued, skipped or failing checks are not passing; generic syntax/README scanning is not a substitute for project-specific integration tests.
4. **Third-party assets:** Review sample candidates listed in each REVIEWER_GUIDE.md and the [account-wide asset audit](PORTFOLIO_ASSET_AUDIT.md). Establish authorship, licensing, attribution, privacy and permissions before asserting compliance.
5. **Recruiter experience:** Each public showcase repository links a concise reviewer guide from its README with grounded entry paths, evidence limitations and source review guidance.

## Remaining manual review gates

- Inspect **completed** CI runs on the newest default-branch commit, fix actual failures, and rerun tests. A pending run cannot be counted as a success.
- Verify vulnerable dependency alerts and license compatibility before updating package versions; safe automated updates may still break application behavior.
- Confirm asset provenance and permission for any dataset, illustration, screenshot, spreadsheet, document or third-party template before redistributing it.
- Verify recruiter-facing demos, screenshot claims and local instructions using a clean environment rather than assuming links mean software runs.
- In case of leaked credentials, revoke/rotate credentials and assess exposure; history rewriting does not invalidate an exposed secret.

## Interpretation

The list establishes navigation coverage on the default branch, not exhaustive review of all files, project correctness or absence of secrets. For GitHub security and test findings, rely on repository-specific results and direct source inspection.
