# Security Policy

Thank you for helping keep these projects safe.

## Reporting a vulnerability

**Do not publish exploit details, access tokens, passwords, private data, or other sensitive information in a public GitHub issue, discussion, or pull request.**

For a repository that offers GitHub private vulnerability reporting, open that repository's **Security** tab and select **Report a vulnerability**. If the option is not available, use the repository owner's [GitHub profile](https://github.com/JamieChristian22) to request a private reporting channel **without including sensitive details in the public message**.

When contacting the maintainer privately, provide the affected repository, a concise impact assessment, and safe reproduction steps. Please do not attempt to access other people's data or disrupt services.

## Scope and expectations

- These repositories may contain learning labs, synthetic demonstrations, documentation, and experimental code. Do not assume any project is deployed in production.
- Do not submit real credentials or personal, financial, health, or customer data as reproduction material.
- Never commit API keys, cloud credentials, or secret environment files.
- Third-party components and dependencies have their own security and disclosure procedures.
- The maintainer will evaluate credible reports as capacity permits; no fixed response or remediation time is guaranteed.

Projects with their own `SECURITY.md` take precedence over this account-wide default.
