# Contributing

These repositories contain independent technical portfolios, educational labs, demonstrations, and ongoing projects. Contributions are considered case by case; not every repository accepts external feature work.

## Before proposing a change

1. Read the project's README, LICENSE, and any repository-specific contribution or security guidance.
2. For corrections or improvements, open an issue describing the problem and expected outcome, where issues are enabled.
3. Keep pull requests focused, explain what changed, and include verification steps or screenshots when useful.
4. Preserve attribution, license notices, and evidence that distinguishes synthetic or modeled outputs from real deployments.

## Safety and privacy

- Never include credentials, access tokens, private keys, real customer or employee data, or confidential documents.
- Prefer synthetic or openly licensed sample data and cite its origin and license.
- Do not execute deployment, administrative, or destructive scripts against live resources as part of a contribution.
- Report suspected vulnerabilities privately; see [SECURITY.md](SECURITY.md) rather than publishing details.

## Reviews

Maintainers may request revisions or decline a proposal based on project scope, licensing, safety, maintenance capacity, or portfolio integrity. Each repository's own CONTRIBUTING file takes precedence over these account-wide guidelines.
